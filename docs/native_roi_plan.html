Native-space ROI support for dwi-tracts

1. Bottom line

The change is feasible and — done the recommended way — requires no functional change to the downstream TSA analysis at all.

The deformation of the consensus tract into subject space (process_tsa_subject) depends only on the subject's diffusion↔template warp (reg3G), which is completely independent of where an ROI was originally defined. As long as each subject's probtrackx path-density output lands on the shared template grid — exactly as it does now — the group averaging, consensus-tract estimation, and TSA regression are unaffected.

The trick is to resolve "native" into the template grid at the pre-processing (probtrackx) stage, per subject, rather than pushing native space downstream. The subject-specific ASHS label is warped into template space and used as the seed/target mask; the individualisation you want (subject-true BA35 / hippocampal anatomy) is fully preserved, but the pipeline keeps a single common grid end-to-end.

The bulk of the new work is therefore where you already expected it: pre-processing — a per-subject registration chain from ASHS (T2 hires slab) into the Mean3G template, plus a small JSON-schema extension and a group-consensus ROI builder. The analysis package dwitracts/ needs only trivial, optional edits.

2. How the pipeline uses coordinate spaces today

There are exactly two spaces in play, and they meet in one place.

TEMPLATE = study template Mean3G (a.k.a. "standard"/"mni" in the code)NATIVE = a single subject's diffusion (FA/DWI) space
TEMPLATE ROI masks in data/rois/mtl-fix/*.nii.gz (LC_L, Ent_L, …) │ │ probtrackx (run_probtrackx.py) │ -x SEED seed mask defines the OUTPUT reference space │ --xfm Mean3G_warp2FA template → native (applied to masks internally) │ --invxfm FA_warp2Mean3G native → template │ --os2t --otargetpaths ▼ TEMPLATE per-subject probtrackX/<net>/<seed>/target_paths_<target>.nii.gz │ (every subject on the SAME grid — no --seedref, so seed grid wins) │ │ dwitracts.main (group level — ALL of this is template space) │ compute_bidirectional_averages ← sums target_paths across subjects │ compute_tract_distances ← reads rois_dir masks for seed distance │ estimate_(uni|bi)directional_tracts, gaussians, polylines │ compute_average_orientations → avrdir_<tract>.nii.gz ▼ TEMPLATE consensus tract final/tract_final_bidir_<tract>.nii.gz │ + orientation field avrdir/avrdir_<tract>.nii.gz │ │ process_tsa_subject() ── per subject ── │ vecreg / applywarp -w reg3G/Mean3G_warp2FA (TEMPLATE → NATIVE) ▼ NATIVE consensus tract + orientations resampled into subject DWI space │ → per-voxel OLS regression against raw DWI (the TSA betas) │ applywarp -w reg3G/FA_warp2Mean3G (NATIVE → TEMPLATE) ▼ TEMPLATE <stat>_mni_<tract>.nii.gz → smoothed, masked → GLM

Key source anchors:

  • preprocess/run_probtrackx.py — builds the probtrackx2 command; seed is -x {rois_dir}/{seed}.nii.gz, and --xfm/--invxfm are the subject reg3G warps (lines ~113–125, 190–191).
  • dwitracts/main.py:103 — initialize() loads rois[0] to fix self.V_img, the reference affine/grid for every group volume.
  • dwitracts/main.py:237 — compute_bidirectional_averages sums target_paths across subjects with one shared affine — this is only valid because they are all on the template grid.
  • dwitracts/main.py:347 — compute_tract_distances loads each rois_dir/{roi} mask onto self.V_img.affine and uses it as the flood-fill seed for step-distance ordering.
  • dwitracts/main.py:1370–1371, 1452–1473, 1604–1605 — process_tsa_subject: the only place native subject space appears, driven purely by reg3G warps.

3. The two invariants the downstream depends on

The entire group + TSA stack is agnostic to an ROI's origin. It only requires:

Invariant A — one shared grid. Every subject's target_paths_<target>.nii.gz must sit on the identical template voxel grid (so they can be summed voxel-wise in compute_bidirectional_averages).

Invariant B — one template ROI file per ROI. A single rois_dir/<roi>.nii.gz on that same grid must exist, because initialize() uses one to define the reference affine and compute_tract_distances/estimate_* use each as the distance seed.

Neither invariant knows or cares whether an ROI was drawn in MNI or came from a subject's ASHS segmentation. This is the crux of the feasibility answer: satisfy A and B, and the consensus-tract-into-subject-space machinery is untouched.

4. Impact on the consensus-tract → subject-space TSA step

Your specific worry — "the downstream analysis of tract-specific anisotropy requires deforming a consensus tract into subject space" — resolves cleanly:

  • The consensus tract is built in template space from the path densities, then warped to each subject with reg3G/Mean3G_warp2FA. That warp is a diffusion↔template registration produced by bedpostx pre-processing; it has nothing to do with the ROIs. Whether BA35 was an MNI blob or a subject-specific ASHS label, the consensus tract is still a template-space image and still warps by the same subject field.
  • process_tsa_subject never opens an ROI file. It consumes tract_final_bidir_* and avrdir_* only. So it is entirely insensitive to this change.
  • The one thing that does change is the anatomy of the consensus tract itself: tracts will now terminate at subject-true transentorhinal / hippocampal locations (warped to the template) instead of a one-size MNI ROI. That is the scientific improvement you want, and it flows through automatically — no code path special-cases it.

Conclusion: the downstream TSA deformation is safe. The change lives almost entirely upstream of it.

5. Two ways to introduce native ROIs

Option A — resolve to template at probtrackx recommendedOption B — run probtrackx natively
Per subject, warp the ASHS label into Mean3G space and use it as the seed/target mask. --xfm/--invxfm unchanged; outputs stay on the template grid. Warp LC into native space, keep ASHS native, run probtrackx with no --xfm. Outputs come out in native space.
Invariant A/B preserved. Zero downstream change. Subject-specificity preserved (mask is the subject's own anatomy, merely re-gridded). Breaks Invariant A: every subject's target_paths is on a different grid, so compute_bidirectional_averages can no longer sum them. You'd have to add a per-subject warp-to-template step inside the group loop.
Extra cost: one applywarp per native ROI per subject at prep time. More invasive; touches the analysis package; more moving parts.

Recommendation: Option A. It keeps a single common grid, leaves dwitracts/ essentially untouched, and still gives you individualised termination regions. The rest of this plan assumes Option A.

6. Concrete changes, file by file

6.1  JSON schema — declare per-ROI space

Today seeds/targets/exclusion are plain string lists (project/LC-MTL.json). Extend backward-compatibly: a bare string keeps meaning TEMPLATE; an object opts into NATIVE and carries the ASHS lookup.

Before — project/LC-MTL.json

{
  "networks": [
    {
      "seeds":     ["LC_L"],
      "targets":   ["Ent_L", "PirTB_L", "PirT_L"],
      "exclusion": ["LC_Stop","csf","zPlane_86"]
    }
  ]
}

After — LC stays template; transentorhinal target becomes the subject's ASHS BA35

{
  "networks": [
    {
      "seeds":     ["LC_L"],                          // string → space:"template" (default)
      "targets": [
        { "roi": "BA35_L", "space": "native",         // subject ASHS label
          "ashs_side": "left", "ashs_labels": [11] }, // 11 = BA35 (transentorhinal)
        "PirTB_L", "PirT_L"                           // still template
      ],
      "exclusion": ["LC_Stop","csf","zPlane_86"]
    }
  ]
}

For the limbic follow-on, the anterior hippocampus target is CA1/CA2/CA3 with an optional anterior restriction:

{ "roi": "antHC_L", "space": "native", "ashs_side": "left",
  "ashs_labels": [1, 2, 4],          // CA1=1, CA2=2, CA3=4  (DG=3 optional)
  "anterior_fraction": 0.5 }         // optional: keep anterior half of the slab

ASHS label numbers verified against a subject seg and the columns of ashs_dataframe.csv: 1 CA1 · 2 CA2 · 3 DG · 4 CA3 · 8 SUB · 10 ERC · 11 BA35 · 12 BA36 · 13 PHC.

6.2  preprocess/run_probtrackx.py — resolve ROI paths per subject

Currently every mask path is hard-wired as {rois_dir}/{name}.nii.gz (see run_probtrackx_for_seed). Introduce a resolver so a network entry can be a string or a native-ROI object, and normalise the entry lists up front.

def roi_name(entry):
    """A network entry is either 'ROIName' or {'roi': 'ROIName', ...}."""
    return entry['roi'] if isinstance(entry, dict) else entry

def roi_space(entry):
    return entry.get('space', 'template') if isinstance(entry, dict) else 'template'

def resolve_roi_path(entry, subject, rois_dir, subj_native_roi_dir,
                     config_gen, fsl_bin):
    """Return a TEMPLATE-grid mask path for this ROI, generating a subject-
    specific one from ASHS if space == 'native'. Guarantees Invariant A."""
    name = roi_name(entry)
    if roi_space(entry) == 'template':
        return '{0}/{1}.nii.gz'.format(rois_dir, name)          # unchanged path

    # --- native (ASHS) ROI -------------------------------------------------
    out = '{0}/{1}.nii.gz'.format(subj_native_roi_dir, name)
    if os.path.isfile(out) and not config_gen['clobber']:
        return out
    make_native_roi_in_template(
        subject      = subject,
        side         = entry['ashs_side'],
        labels       = entry['ashs_labels'],
        anterior_fr  = entry.get('anterior_fraction', None),
        out_path     = out,          # resampled onto the Mean3G reference grid
        config_gen   = config_gen, fsl_bin = fsl_bin)
    return out

Then run_probtrackx_for_seed takes resolved paths instead of building them from names. The only edits are the three places that interpolate {rois_dir}/{name}.nii.gz:

Critical detail for Invariant A: make_native_roi_in_template must resample onto the exact Mean3G reference grid (applywarp -r utils/Mean3G), so every subject's native ROI — and therefore every target_paths output — shares one affine. Do not let it inherit the ASHS 0.39×0.39×2 mm grid.

6.3  New helper — ASHS label → template mask

ASHS segmentations live at derived/<PTID_DATE>/ashs/final/ashs_<side>_lfseg_corr_usegray.nii.gz in a T2 hires slab (verified: 448×448×30, oblique coronal). The registration chain is the genuinely new pre-processing piece:

# conceptual — the registration chain to build ONE native ROI on the Mean3G grid
def make_native_roi_in_template(subject, side, labels, anterior_fr, out_path, ...):
    seg = ashs_seg_path(subject, side)                 # ASHS T2-slab segmentation
    # 1. binarise the requested label(s) in ASHS space
    run_fsl('fslmaths {seg} -thr {lo} -uthr {hi} -bin {tmp}'...)   # per label, then -add
    # 2. optional anterior restriction (keep anterior fraction of populated slices)
    # 3. ASHS(T2) -> DWI/Mean3G.  Reuse an existing transform if the study already
    #    registers the T2 hires slab or the T1 to diffusion; otherwise:
    #       ASHS-T2  --(rigid, ashs mprage)-->  T1
    #       T1       --(epi_reg / existing)  -->  DWI (native)
    #       DWI      --(reg3G FA_warp2Mean3G) -->  Mean3G  (TEMPLATE)
    # 4. applywarp -r utils/Mean3G  --interp=nn  -> out_path  (Invariant A)
    #    fslmaths out_path -bin out_path

You flagged the tracing pre-processing as "trivial" — this chain is where the real effort sits, but it is standard registration plumbing and, importantly, self-contained: nothing downstream needs to know it happened. If ASHS→diffusion registration already exists in the ADNI pipeline, this collapses to a single applywarp.

6.4  New script — build the group-consensus template ROI (Invariant B)

dwitracts still needs one rois_dir/<roi>.nii.gz per native ROI (for the reference affine and the flood-fill distance seed). Build it once by averaging the per-subject warped native masks:

# preprocess/build_native_roi_group.py  (run once, after native ROIs are generated)
acc = None
for subject in subjects:
    v = nib.load(f'{deriv}/{subject}/dwi/native_rois/{net}/{roi}.nii.gz').get_fdata()
    acc = v if acc is None else acc + v
prob = acc / len(subjects)                       # voxel-wise inclusion frequency
mask = (prob >= 0.30).astype(np.float32)          # e.g. present in ≥30% of subjects
nib.save(nib.Nifti1Image(mask, ref.affine, ref.header),
         f'{rois_dir}/{roi}.nii.gz')              # satisfies Invariant B

This consensus mask is used only for grid definition and distance ordering, not for the actual per-subject targeting (which uses the subject-specific mask). A generous threshold is fine.

6.5  dwitracts/main.py — what changes here

Functionally: nothing. With Invariants A & B satisfied, initialize, compute_bidirectional_averages, compute_tract_distances, the tract estimators, compute_average_orientations, compute_tsa, and process_tsa_subject all keep working unchanged.

Optional, low-risk niceties:

  • Add the native ROI names to project/lc-limbic.rois / lc.rois and *.pairs so the group loops include them (these are just name lists — Ent_L today simply becomes BA35_L, etc.).
  • Optionally record provenance (which ROIs were native) into the tract log dir for reproducibility. Not required for correctness.

7. Risks, edge cases & validation

ConcernHandling
Grid drift — a native ROI resampled onto a slightly different affineAlways applywarp -r utils/Mean3G; assert the output affine equals self.V_img.affine in the group builder. This is the one thing that would silently corrupt compute_bidirectional_averages.
Missing / failed ASHS for some subjectsResolver returns None → skip that subject for that network (mirrors the existing try/except in compute_bidirectional_averages). Log to the tract log dir.
Reverse-direction tracking uses the native ROI as a seedFine — the warped-to-template mask is a normal template-grid seed; output space still template. No special case.
Empty mask after label extraction / anterior cropValidate voxel count > 0 before writing; fail loudly at prep time, not silently at group time.
ASHS T2 slab is a thin coronal slab (2 mm, limited FOV)BA35 & anterior hippocampus are inside the slab, so targeting is fine; just confirm the anterior-restriction logic uses slab geometry, not template Y.

Suggested validation sequence

  • Pick 2–3 subjects; generate their native BA35 in template space; overlay on Mean3G and on the old MNI Ent_L — confirm anatomical plausibility.
  • Run probtrackx for those subjects; confirm target_paths_*.nii.gz have the same affine/shape as a template ROI (fslinfo diff).
  • Run the group steps on the small set; confirm compute_bidirectional_averages produces a sane consensus tract and that process_tsa_subject completes with no new failures.
